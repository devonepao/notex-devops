1.1 Linux File System Hierarchy

  • /bin - Essential command binaries (ls, cp, mv, rm)
  • /sbin - System binaries (fsck, init, route)
  • /etc - System configuration files
  • /home - User home directories
  • /var - Variable files (logs, caches, spool files)
  • /tmp - Temporary files
  • /usr - User programs and data
  • /opt - Optional application packages
  • /proc - Virtual filesystem for process info
  • /sys - Device and kernel information

Chapter 2: Networking & Protocols ▼

2.1 OSI Model

  1. Layer 7 - Application: HTTP, FTP, SMTP, DNS
  2. Layer 6 - Presentation: SSL/TLS, encryption
  3. Layer 5 - Session: Session management
  4. Layer 4 - Transport: TCP, UDP
  5. Layer 3 - Network: IP, ICMP, routing
  6. Layer 2 - Data Link: Ethernet, switches
  7. Layer 1 - Physical: Cables, hubs

2.2 TCP/IP Model

  • Application Layer: HTTP, FTP, DNS, SMTP
  • Transport Layer: TCP, UDP
  • Internet Layer: IP, ICMP, ARP
  • Network Access Layer: Ethernet, WiFi

2.3 HTTP/HTTPS Protocols

HTTP Methods

  • GET: Retrieve resource
  • POST: Create resource
  • PUT: Update/replace resource
  • PATCH: Partial update
  • DELETE: Remove resource
  • HEAD: Get headers only
  • OPTIONS: Get allowed methods

HTTP Status Codes

  • 1xx: Informational (100 Continue)
  • 2xx: Success (200 OK, 201 Created, 204 No Content)
  • 3xx: Redirection (301 Moved, 302 Found, 304 Not Modified)
  • 4xx: Client Error (400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found)
  • 5xx: Server Error (500 Internal Error, 502 Bad Gateway, 503 Service Unavailable)

2.4 DNS (Domain Name System)

DNS Record Types

  • A: IPv4 address
  • AAAA: IPv6 address
  • CNAME: Canonical name (alias)
  • MX: Mail exchange
  • TXT: Text records
  • NS: Name server
  • SOA: Start of authority
  • PTR: Reverse DNS lookup

DNS Resolution Process

  1. Check local cache
  2. Query recursive resolver
  3. Query root nameserver
  4. Query TLD nameserver
  5. Query authoritative nameserver
  6. Return IP address

2.5 Load Balancing

Load Balancing Algorithms

  • Round Robin: Sequential distribution
  • Least Connections: Server with fewest connections
  • IP Hash: Hash client IP
  • Weighted Round Robin: Weight-based distribution
  • Least Response Time: Fastest server

Load Balancer Types

  • Layer 4 (Transport): TCP/UDP level (fast, simple)
  • Layer 7 (Application): HTTP level (smart routing)

2.6 SSL/TLS

TLS Handshake

  1. Client Hello
  2. Server Hello + Certificate

Chapter 8: Site Reliability Engineering (SRE) Principles ▼

8.1 SRE Fundamentals (Google SRE)

Core Principles

  • Embrace Risk: 100% reliability is wrong target
  • Error Budgets: Balance velocity and reliability
  • Toil Reduction: Automate repetitive work
  • Monitoring: Observability over guessing
  • Capacity Planning: Organic growth + launches
  • Emergency Response: Incident management
  • Change Management: Progressive rollouts

8.2 Error Budgets

Calculation

  • SLO: 99.9% availability
  • Error Budget: 0.1% = 43.8 minutes/month
  • If budget exceeded: freeze releases, focus on reliability
  • If budget available: ship features faster

8.3 Toil

Definition

  • Manual
  • Repetitive
  • Automatable
  • Tactical (not strategic)
  • No enduring value
  • Scales linearly with service growth

Target: <50% time on toil

8.4 Incident Management

Incident Response Roles

  • Incident Commander: Overall coordination
  • Operations Lead: Technical response
  • Communications Lead: Stakeholder updates
  • Planning Lead: Resource tracking

Incident Lifecycle

  1. Detection: Alert fires or user report
  2. Triage: Assess severity and impact
  3. Mitigation: Stop the bleeding
  4. Resolution: Fix root cause
  5. Postmortem: Learn and improve

Severity Levels

  • SEV-1: Critical impact, all hands on deck
  • SEV-2: Major impact, significant degradation
  • SEV-3: Minor impact, workaround available
  • SEV-4: Minimal impact, cosmetic issues

  • Optimize queries (avoid N+1)
  • Use caching (Redis, Memcached)
  • Partition large tables
  • Archive old data
  • Use read replicas
  • Implement query timeout

9.6 Database Backup & Recovery

Backup Types

  • Full Backup: Complete database copy
  • Incremental: Changes since last backup
  • Differential: Changes since last full backup
  • Point-in-Time: Restore to specific timestamp

Best Practices

  • Automate backup process
  • Test restore procedures
  • Store backups off-site
  • Encrypt sensitive backups
  • Monitor backup success
  • Define RPO and RTO

11.1 Scalability Patterns

Horizontal vs Vertical Scaling

  • Horizontal: Add more machines (scale out)
  • Vertical: Add more power (scale up)

Stateless vs Stateful

  • Stateless: No session data, easy to scale
  • Stateful: Session data, sticky sessions needed

11.2 Caching Strategies

Cache Patterns

  • Cache-Aside: App manages cache
  • Read-Through: Cache loads on miss
  • Write-Through: Write to cache and DB
  • Write-Behind: Async write to DB
  • Refresh-Ahead: Proactive refresh

Cache Eviction Policies

  • LRU: Least Recently Used
  • LFU: Least Frequently Used
  • FIFO: First In First Out
  • TTL: Time To Live

11.3 Message Queues

Queue Types

  • Point-to-Point: One consumer per message

  • Priority Queue: Ordered by priority
  • Dead Letter Queue: Failed messages

  • Apache Kafka

11.4 Microservices Architecture

11.5 CAP Theorem

  • Consistency: All nodes see same data
  • Availability: Every request gets response
  • Partition Tolerance: System works despite network partitions
